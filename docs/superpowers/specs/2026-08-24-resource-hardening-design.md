# 资源专项 — 设计文档（v1）

日期：2026-08-24
状态：v1 已确认（设计要点在对话中通过）
目标：0.1.0 发布与投产前五维专项之第 4 项「资源」。定位：验证并建档「资源利用率超越对标」的证据链。专项形态为压缩形态——**实测建档 + 决策门微优化**：不手写社区已提供的功能（不替换 prometheus 存储/编码器），遵守项目规则「减少手写代码、优先使用社区资源」。
约束：本专项为五维递进的第 4 项——不得破坏第 1 项（安全性）、第 2 项（稳定性）、第 3 项（性能）成果（§6 回归门禁），其成果构成第 5 项（功能）的不可破坏基线。

## 3. 实测方案（四轴）

### 3.1 环境与制品

- 环境：两台真机（Dell 10.10.90.70 / 浪潮 10.10.90.80）+ 本地 mock。
- 制品：`%TEMP%\opencode\redfish-resource-run\` 原始输出落盘（沿用性能维制品惯例），验收记录逐项引用文件路径。

### 3.2 内存轴

- 真机：exporter 进程 WS/私有实测；快照占比账面估算（组件级）与 RSS 实测对照。
- mock：RSS-vs-BMC 数曲线（1/2/4 BMC）→ 每 BMC 内存系数（registry + 预编码缓存 + 采集瞬态），验证/修正性能维移交的 ~1.1MB/BMC 增量。
- 输出：内存构成表 + 多 BMC 线性增长模型与上限。

### 3.3 CPU 轴

- 三态采样：idle / 采集轮进行中 / /metrics 抓取窗口，进程 CPU 采样（Get-Counter 或等价 PowerShell），各态均值/峰值。

### 3.4 连接轴

- 轮次内 exporter↔BMC TCP/TLS 连接建立/复用行为（按 BMC IP 过滤采样，统计新建连接数 vs 复用数），判定 keepalive/池化行为。
- 处置走决策门：若未复用且为 nv-redfish 内部行为、不可配置 → 如实记录 + backlog（不碰核心依赖链）。

### 3.5 请求量轴

- 每轮每 BMC 请求数：采集面推算（快/慢组资源清单）+ `redfish_scrape_duration_seconds` 样本计数佐证；与对标（每轮全量重爬）对比。

## 4. 对标证据与内存模型文档

### 4.1 对标对比表（资源维度）

- 行 = 资源特性（缓存/请求量/连接/运行时内存），列 = idrac / fishymetrics / sapcc（源码级定性，复用差距表结论）+ 我们（真机实测）。
- 结论如实标注「领先 / 持平 / 局限」，不夸大。

### 4.2 内存模型文档化（design.md 新增资源节）

- per-BMC 内存构成：registry + 预编码缓存 ~1.1MB + 采集瞬态；多 BMC 线性增长系数（mock 实测）；上限：分页防御上限（单页 64MiB / 页数 1000 / 累计成员 200,000）已约束最坏情况。
- 预编码缓存增量复核结论（性能维 spec §9 移交项）。
- backlog 登记：实测发现的任何热点 / 未复用连接等发现逐一留痕。

## 5. 验收标准（定义「完成」）

1. **S1**：§3 四轴实测完成，原始证据落盘。
2. **S2**：§4.1 对标对比表 + 结论（如实标注）。
3. **S3**：§4.2 内存模型与缓存增量复核文档化（design.md 资源节 + 验收记录）。

5. **S5**：决策门执行记录完整（发现 → 判定 → 批准/backlog 全程留痕）。

## 6. 回归门禁（不破坏前三项成果 + 冻结语义）

1. **安全回归**：config/http/bmc/pagination/auth 测试全绿；cargo audit（白名单内零新增）/ deny 保持全绿。
2. **稳定回归**：stability/scraper/integration/soak 基建全绿；状态机、冷却、发布语义不受影响（本维默认零代码改动，回归为确认性验证）。
3. **性能回归**：perf_test（`#[ignore]` 本地）在 ±5% 容差内；等价性测试全绿。
4. **语义冻结**：本维不改编码/存储路径；若决策门微优化获批准，须重跑上述全部门禁并显式声明改动。
5. **验收记录**：`docs/audit/2026-08-24-resource.md`。

## 8. 明确不做（YAGNI / backlog）

| 项 | 理由 |
|---|---|
| prometheus 存储替换 / 手写编码器 | 违反「优先社区资源」规则（D1 排除） |
| 驻留 / Box<str> 内存压降 | 存储为 prometheus 自有拷贝，不改存储则无效 |
| N×walk 共享预取 / per-BMC 并发 | 性能维已排除（风险递增项）；不重开 |
| gzip/流式输出 | Prometheus 抓取侧无需；维持 backlog |
| 流式响应上限（nv 无流式 fetch） | 安全维已记 backlog；维持 |

## 9. 风险与依赖

| 风险 | 处置 |
|---|---|
| 真机不可达（环境因素） | 如实记录未执行原因，改 mock 全量证据；验收记录如实标注 |
